# M6 — 2-D and Hole Types Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first part of M6: the 2-D and hole types of D15b §2 and §3 on the M3 framework. They are `face`, `adaptive_2d`, `trace`, `engrave`, `chamfer_2d`, `bore` and `drill`. Each type gets its parameters, validation, strategy, a golden G-code reference project and a translation-invariance test.

**Architecture:**
- `fluut-model`:
  - a field table, a resolved struct and the D15b §2–§3 validation rules for each type;
  - a `Duration` field kind (D15b §1.1);
  - tool additions: `shape = "drill"`, `point_angle_deg`, `pitch`, and `optimal_load` in presets. V tools also need a half-angle and a tip diameter (see Scope decisions);
  - `PostCaps` learns about helices and canned cycles.
- `fluut-cam`:
  - one strategy module per type in `strategy/`;
  - the S3 adaptive spike promoted to `strategy/adaptive_2d.rs`, with the exact engagement code in `engage.rs`;
  - shared hole finding (`holes.rs`) for `drill` and `bore`.
  
  Framework edits are kept small:
  - `StrategyInput.stock`: the stock box in W, used by `face` and by open pockets in `adaptive_2d`;
  - a stay-down link is checked against the next cut's region only;
  - `wall_pieces` can take top edges as well as bottom edges.
- `fluut-core`: fills `StrategyInput.stock` and the new `PostCaps` fields. At post time, a tap cycle feeds at rpm × pitch.
- `fluut-cli`: reference projects with hand-written STEP parts, golden G-code, and translation invariance for every new project.

**Tech Stack:** as M3. No new crates.

**Design:** [D15b](../design/D15b-toolpath-parameters-2.md) §1–§3, §9; [D15](../design/D15-toolpath-parameters.md) §1, §2, §7; [D09](../design/D09-strategies.md) §2, §3; [D08](../design/D08-toolpath-framework.md); [D10](../design/D10-post-engine.md) §5; [S3 report](spikes/s3-region-2d.md); M3 plans [vertical slice](2026-11-01-m3-vertical-slice.md) and [parallel](2026-11-01-m3-parallel.md).

## Scope decisions

- **In-process stock** (D08 §7) does not exist yet. The types do not update stock, and `rest_from = "previous"` stays the error `param.geometry.rest_from.unsupported`, as for `pocket_2d`.
- **V tools.** `engrave` and `chamfer_2d` need the half-angle α and the tip radius Rt (D07 §1), but the tool format has no keys for them. This plan adds `half_angle_deg` and `tip_diameter` (default 0) for `v` and `taper` tools to spec 02 §2.4. A `v` or `taper` tool without `half_angle_deg` is not a V tool.
- **Drill tools.** `shape = "drill"` has corner radius 0. `point_angle_deg` defaults to 118.
- **Heights per hole** (D15b §1.6). `drill` and `bore` resolve the heights once for each hole, with `selection` set to that hole's Z range. Parameter validation runs once, on the selection range of all holes.
- **Holes.** A hole is one or more coaxial cylindrical faces whose axis is parallel to Z. Their axes must match within `machining_tolerance`. A face counts as a hole when its material is outside the cylinder (the face normal points to the axis), and as a boss otherwise. A cone face below the deepest cylinder, on the same axis, gives `to_cone_tip` its tip.
- **`face`.** The stock outline is the XY box of the Setup stock. One-way passes (`climb`, `conventional`) do not stay down between passes. They follow `linking.retract` and lift as for any other link.
- **`trace` in `curve` mode.** The Z at a point of the path is the Z of the nearest point, in XY, of the selected curves, sampled at `machining_tolerance`. It is applied to the pass as a Z profile (as for tabs).
- **`chamfer_2d` tip gouge.** A flat cutter of the tip diameter (at least 0.01 mm) is dropped onto the model along the tool-centre path. If it stops above the tip Z by more than the tolerance, the tip would touch the model.
- **`drill` cycles.** The `dwell` cycle is posted as `spot` with its dwell. The `chip_break_retract` length has no cycle parameter in D10 §5, so the post's own gap is used when the cycle is expanded. `retract_mode = "retract"` links between holes at the retract height. The built-in posts use G99, so for native cycles the R plane decides the return height; that is recorded as a follow-up.
- **`adaptive_2d`.** The path is the same at every level, because there is no in-process stock. It is computed once per area and reused, with a ramp only on the first entry of each level. Links between passes stay down when the straight move stays inside the cleared region. The speed target is < 1 s per level on the S3 shapes A, B and C (S3 report §7).
- **`engrave`** needs an exact medial axis of lines and arcs (CH-17). The S3 report estimates 3–5 weeks for a robust version. If there is no time for it in this plan, `engrave` gets its parameters and validation only, and `generate` reports `cam.type.unavailable`, as `parallel` did in M3.
