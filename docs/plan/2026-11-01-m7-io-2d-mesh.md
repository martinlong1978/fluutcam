# M7 — 2-D and Mesh Importers Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read DXF and SVG into wire bodies and STL into mesh bodies (D05 §1–§4), with all input treated as untrusted. A DXF outline drives `contour_2d` and `pocket_2d` from `fluut calc` and `fluut post`. This plan covers the `fluut-io-2d` and `fluut-io-mesh` part of M7. Bitmap relief (D05 §5), the STL writer (D05 §2.4), `fluut-post-import`, `fluut-sim` and `fluut-script` are separate plans.

**Architecture:**
- `fluut-io-2d` (layer 2) has two readers, both written here:
  - **DXF:** a reader of ASCII group-code pairs, in sections, blocks and entities.
  - **SVG:** an XML tree from `roxmltree`, walked with the transforms composed. Path data, transform lists, lengths and point lists use their own parsers.
  - Both produce `Import2D { wires, report }`.
  - A shared `conic` module maps circles and ellipses under any affine transform. A circle that a non-uniform scale or a skew distorts becomes an ellipse, so arcs are never turned into Béziers.
- `fluut-topo` gets an additive `MeshBody`: welded positions, triangles, and per-edge triangle neighbours (spec 03 §3.2.5).
- `fluut-io-mesh` (layer 2) reads binary and ASCII STL. It welds vertices, builds the adjacency, votes on the orientation, and reports open and non-manifold edges.
- `fluut-core`'s model store dispatches on the source `kind`:
  - DXF and SVG give one wire body per layer (DXF) or per file (SVG).
  - STL is read and checked, but no strategy takes a mesh yet, so its bodies are not offered to toolpaths.
- `fuzz/` gets targets for DXF, SVG and STL, with seeds.

**Tech Stack:** as M3. `fluut-io-2d` adds `roxmltree` (MIT OR Apache-2.0, no dependencies). D05 names the `dxf` and `svgtypes` crates; neither is used (Scope decisions).

**Design:** [D05](../design/D05-mesh-2d-import.md) §1–§4 and §6, [D03](../design/D03-topology-bvh.md) §1.1; spec 02 §2.6 and §2.6.2, 03 §3.2.4–§3.2.5, 06 §6.3.

## Global Constraints

All earlier Global Constraints apply. In addition:

- Input is untrusted (spec 06 §6.3):
  - every reader returns errors and never panics;
  - file size, entity, curve, triangle, nesting and expansion counts are bounded by a `Limits` struct with documented defaults;
  - each reader has a `cargo-fuzz` target.
- Test files are hand-written, in the test sources or `tests/data/`. No exporter output and no third-party samples are committed.
- `fluut-core` and `fluut-cli` changes stay small; M4 also changes `fluut-core`. Do not modify `crates/fluut-cam` (parallel session).
- Units:
  - DXF and STL never assume a unit (spec 02 §2.6.2). The project's `unit` is required. `$INSUNITS` is only suggested, in the error message.
  - SVG takes its unit from the document (D05 §4) unless the project sets one.
- No DeskProto-derived content.

## Scope decisions

- **DXF reader:** own reader, not the `dxf` crate (CH-09). Group-code pairs are simple to read. An own reader lets every count and length be bounded, and keeps the dependency tree small.
- **Binary DXF:** detected and reported as unsupported. It is rare in practice and can be added later behind the same entity layer.
- **SVG path data:** own parser, not `svgtypes`. The grammar is small (numbers, flags, commands), and `svgtypes` would bring `kurbo` along.
- **XML:** `roxmltree`, with its node limit set from `Limits`. DTDs are allowed, because Illustrator writes a `DOCTYPE`. `roxmltree` bounds entity expansion and never loads external entities.
- **Bodies:**
  - DXF: one wire body per layer, in the order in which layers first appear in `ENTITIES`, with ids `b-1`, `b-2`, …; the body name is the layer name. Selecting by layer means selecting the body.
  - SVG: one body, `b-1`. Re-import matching (spec 03 §3.5) is M4.
- **Colours:** not kept. `WireBody` has no attribute field; layers are kept through the bodies.
- **Chaining:** curves stay in file order. The report counts closed chains and open ends, found with `tol_model`. `fluut-cam` chains the curves for toolpaths (D08).
- **SVG styling:** CSS, `style`, `display` and `visibility` are ignored, so hidden elements are imported. Text, images, filters, gradients, masks, clip paths, markers and patterns are reported as ignored.
- **STL in the model store:** the file is read and checked, and its warnings are reported. No toolpath type takes a mesh yet, and `fluut-cam` (parallel session) has no mesh body kind. So an STL source gives the warning `model.geometry.mesh.unused` and no bodies.
- **Mesh regions and BVH** (D03 §1.1–§1.2): later, with the first mesh strategy. This plan builds the adjacency that they need.

## Review Focus

1. **Arc direction and OCS:**
   - bulge sign;
   - arcs with extrusion `(0, 0, −1)`;
   - mirrored and rotated `INSERT`s;
   - SVG arcs under the y flip and under rotation with non-uniform scale.

   Each must keep its point set and sweep. Tests compare points sampled along the curves.
2. **Units:**
   - DXF and STL without a project unit are errors;
   - `$INSUNITS` is only suggested;
   - SVG `mm`/`in`/`px` documents with and without `viewBox` come out in mm.
3. **Untrusted input:**
   - a block that inserts itself, nesting deeper than 16, an exponential `INSERT` fan-out and an exponential `use` fan-out;
   - huge counts in an STL header, and truncated files.

   Each gives an error or a reported cut-off, never a panic, a hang or an unbounded allocation.
4. **Welding:** vertices within `tol_model` merge to the first one in file order. The result does not depend on any hash order.

### Task 2: DXF reader

**Files:** Create `crates/fluut-io-2d/{Cargo.toml, src/lib.rs, src/conic.rs, src/report.rs, src/dxf.rs, src/dxf/tests.rs}`; modify `Cargo.toml` (workspace dependency).

- `read_dxf(bytes, &Options) -> Result<Import2D, ReadError>`.
  - `Options { scale, tol_model, limits }`: `scale` is mm per drawing unit.
  - `ImportReport` holds:
    - the suggested unit;
    - ignored and unsupported entity counts by name (`BTreeMap`);
    - dropped degenerate curves;
    - closed chains and open ends;
    - warnings.
- Group-code pairs:
  - a code line is a trimmed integer, and the value line keeps leading spaces;
  - `\r\n` and `\n` are both accepted, and bytes are read as lossy UTF-8;
  - an error gives the line number.
- Sections:
  - `HEADER`: `$INSUNITS`.
  - `BLOCKS`: name, base point and entities.
  - `ENTITIES`.
  - Everything else is skipped.
- Entities:
  - `LINE`.
  - `ARC` and `CIRCLE`, in OCS by the arbitrary-axis algorithm.
  - `LWPOLYLINE` and 2-D `POLYLINE`/`VERTEX`/`SEQEND`, with bulges: `θ = 4·atan(bulge)`, positive counter-clockwise about the extrusion.
  - 3-D `POLYLINE` as a line chain; polyface and polygon meshes are unsupported.
  - `SPLINE`:
    - control points, knots and weights;
    - fit points only: global cubic interpolation with chord-length parameters and averaged knots.
  - `ELLIPSE`; a ratio of 1 becomes a circle.
  - `INSERT`:
    - scale, rotation, column and row arrays, and extrusion;
    - entities on layer `0` take the insert's layer;
    - nesting is limited to 16;
    - the curve budget is checked before each expansion.
- Unsupported (counted): `3DFACE`, `MESH`, `3DSOLID`, `REGION`, `BODY`, `SURFACE` and polyface meshes. Ignored (counted): text, dimensions, hatches, points, leaders, images and viewports.
- `conic`:
  - `transform(curve, affine)` for lines, circles, ellipses and B-splines;
  - an ellipse's principal axes come from its conjugate diameters;
  - the parameter is shifted so that `C′(t) = A(C(t + t₀))` traces the same points.
- [x] **Step 1:** Tests:
  - each entity kind;
  - bulge `±1` and `±0.4142` (quarter arcs);
  - an arc and a bulge polyline with extrusion `(0, 0, −1)`, mirrored in X;
  - nested and mirrored inserts, and a column and row array;
  - a spline from control points and one from fit points (passes through them);
  - layers to bodies;
  - `$INSUNITS` suggestions;
  - chain report on an open and a closed outline;
  - `conic` against sampled points under rotation, mirror, non-uniform scale and skew.
- [x] **Step 2:** Robustness tests:
  - truncated pairs, a non-numeric code, a missing `EOF`, binary DXF;
  - a self-inserting block, nesting 17 deep, a 10¹⁰-curve fan-out;
  - NaN and infinite coordinates, zero radii, a spline knot count mismatch.

### Task 3: SVG reader

**Files:** Create `crates/fluut-io-2d/src/svg.rs`, `crates/fluut-io-2d/src/svg/{path.rs, tests.rs}`.

- `read_svg(bytes, &Options) -> Result<Import2D, ReadError>`; here `scale: None` means the document's units.
- Document units:
  - root `width`/`height` in `mm`, `cm`, `in`, `pt`, `pc`, `Q` or `px`, with `viewBox` and `preserveAspectRatio` (align and `meet`/`slice`, or `none`);
  - user units are px at 96 per inch when there is no `viewBox`;
  - Y is flipped about the viewport's bottom edge, so the drawing keeps its look with Y up.
- Elements:
  - `path`, `rect` (with `rx`/`ry` corners as quarter ellipses), `circle`, `ellipse`, `line`, `polyline` and `polygon`;
  - `g` and nested `svg` (by `x`/`y`);
  - `use` of an element or a `symbol`, by `href` or `xlink:href`, with a depth limit and cycle detection;
  - `defs` and unused `symbol`s are not drawn;
  - ignored elements are counted.
- Transforms: `matrix`, `translate`, `scale`, `rotate` (with a centre), `skewX` and `skewY`, composed from the root down.
- Path data:
  - all commands, absolute and relative;
  - compact numbers (`1.5.5`, `-1-2`, `1e-3`) and compact arc flags (`a1 1 0 00 1 1`);
  - `S`/`T` reflection;
  - an arc is converted to centre form (SVG 2 appendix B.2.4), and its radii are scaled up when too small;
  - a zero radius gives a line;
  - `C` and `Q` become Bézier B-splines.
  - Bad path data stops that path at the last good command and is reported, as SVG renderers do.
- [x] **Step 1:** Tests:
  - each command, absolute and relative, and the number and flag grammar;
  - arcs with each flag combination (end point reached, sweep side);
  - an arc under `rotate` with `scale(2 1)` becomes an ellipse with the right points;
  - `circle` under `scale(1 2)` becomes an ellipse;
  - `mm`, `in` and `px` documents, with and without `viewBox`;
  - `use` of a `symbol`, a self-referencing `use`, and a `use` fan-out past the curve limit;
  - a `DOCTYPE` with an external DTD is read; an entity bomb and an external entity are errors;
  - ignored elements are reported.
- [x] **Step 2:** Fail, implement, pass.

### Task 4: STL reader and mesh bodies

**Files:** Create `crates/fluut-topo/src/mesh.rs`, `crates/fluut-io-mesh/{Cargo.toml, src/lib.rs, src/weld.rs, src/tests.rs}`; modify `crates/fluut-topo/src/lib.rs`, `Cargo.toml`.

- `MeshBody { name, tol_model, positions, tris, neighbours }`. `neighbours[t][k]` is the triangle across edge `k`, or `NONE` at an open or non-manifold edge.
- `read_stl(bytes, &Options) -> Result<ImportMesh, ReadError>`, with `Options { scale, tol_model, limits }`. Reading:
  - binary when the size is `84 + 50·n` (D05 §2.1), otherwise ASCII;
  - the count is checked against the size before anything is allocated;
  - ASCII keywords are case-insensitive, with any whitespace;
  - `endsolid` followed by another `solid` is accepted (several solids, one body).
- Welding (D05 §2.3):
  - cells of `2·tol_model`, with vertices sorted by cell and the 27 neighbouring cells found by binary search (no hash map);
  - union-find, where the representative is the first vertex.
- After welding:
  - triangles with area below `tol_model²`, or with two corners merged, are dropped and counted;
  - half-edge matching uses sorted edge keys;
  - orientation is voted against the file normals: if most non-zero file normals disagree with the vertex order, every triangle is flipped and reported;
  - the report counts open edges (and the boundary loops they form), non-manifold edges, edges used twice in the same direction (inconsistent orientation), dropped triangles and the solid names.
- [x] **Step 1:** Tests:
  - binary file with a header starting `solid`;
  - ASCII with mixed case and extra whitespace;
  - welding at `tol_model` (merged at 0.4·tol, kept apart at 3·tol, first vertex kept);
  - a closed tetrahedron (no open edges, all neighbours set), an open box (one loop of 4 edges), and a non-manifold fin;
  - an all-flipped file is flipped back;
  - degenerate triangles are dropped.
- [x] **Step 2:** Robustness tests:
  - truncated binary and ASCII files;
  - a count of `u32::MAX` in a short file;
  - NaN vertices;
  - more triangles than the limit;
  - tokens longer than the limit.
- [x] **Step 3:** Fail, implement, pass.
