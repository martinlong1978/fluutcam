# S3 — 2-D Geometry Spike Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Find out whether `cavalier_contours` (OQ-06) can carry all 2-D region work of D08 §3, and whether adaptive clearing can run on exact arc regions without a grid (CH-16). Exit criterion from the roadmap: a working adaptive pocket on 3 test shapes; CH-13 and CH-16 to CH-19 updated.

**Architecture:** The spike starts the layer-4 crate `fluut-cam` with the region module `region` (`Region2`, `Loop2`, `Seg2`), which is meant to be kept. The pocket and adaptive prototypes go in `fluut-cam/src/spike/` behind no feature flag; they may be thrown away or reworked in M3. Measurements are printed by an example binary, `cargo run -p fluut-cam --example s3 --release`.

**Tech Stack:** as M2; adds `cavalier_contours` 0.9 (MIT OR Apache-2.0, `f64` arithmetic, lines and arcs as bulge polylines, no integer grid).

**Design:** [`../design/D08-toolpath-framework.md`](../design/D08-toolpath-framework.md) §3, [`../design/D09-strategies.md`](../design/D09-strategies.md) §2.2–2.3, [`../design/challenges.md`](../design/challenges.md) CH-13, CH-16 to CH-19.

## Global Constraints

All M0 to M2 Global Constraints apply. In addition:

- Spike code is time-boxed: the region module gets full tests; the prototypes get only the tests that back the numbers in the report.
- No grids or pixel maps anywhere, also not as a fallback inside the prototypes (DC-02 in the spec).
- The report states numbers measured on this machine in release builds, with the shapes and parameters used.

## Review Focus

1. **Orientation**: outer loops CCW, holes CW after every operation; an offset that splits a loop into two keeps each piece correctly oriented.
2. **Boolean consistency**: `area(A ∪ B) + area(A ∩ B) = area(A) + area(B)` and `area(A \ B) = area(A) − area(A ∩ B)` within tolerance, on random arc regions.
3. **Exact engagement**: φ(p) from circle and region arcs agrees with a fine numerical integration within 1e-6 rad.

### Task 1: `fluut-cam` crate and the region types

**Files:** Create `crates/fluut-cam/{Cargo.toml, src/lib.rs, src/region.rs, src/region/tests.rs}`.

- `Seg2 { a: Point2, b: Point2, bulge: f64 }` (bulge 0 = line; `tan(sweep/4)`, sign = direction), `Loop2 { segs }` closed, `Region2 { loops }` (outer CCW, holes CW).
- Conversion to and from `cavalier_contours::polyline::Polyline<f64>`.
- `area`, `contains(p) -> Inside { In, On, Out }` (winding with an `On` band of `tol`), `support(dir) -> (min, max)` exact over arcs, `bbox`.
- Constructors for tests: `rect`, `circle`, `polygon`, `with_hole`.
- [x] **Step 1:** Tests: areas of rectangle, circle, rectangle with circular hole; `contains` in, on, out; `support` of a circle at 30°; round-trip through `Polyline`.
- [x] **Step 2:** Fail, implement, pass; `cargo deny check` accepts the new dependency.

### Task 2: Offsets

- `Region2::offset(d)` through `Shape::parallel_offset` (positive grows the region). Holes and outer loops offset together, so a hole that grows into the boundary removes material correctly.
- [x] **Step 1:** Tests: rectangle in and out (rounded corners outside: arcs of radius d); circle; rectangle with hole, offset until the hole meets the outside (one loop splits or vanishes); an offset that empties the region returns no loops; orientation after each.
- [x] **Step 2:** Fail, implement, pass.

### Task 3: Booleans on multi-loop regions

- `union`, `intersect`, `subtract` built from the polyline booleans of `cavalier_contours`, which work on pairs of single loops only: outer loops are combined pairwise, then holes are subtracted.
- [x] **Step 1:** Tests: overlapping rectangles, disjoint, contained, touching edge; a region with a hole minus a disc that crosses the hole. Property test (Review Focus 2) on random rectangles and discs.
- [x] **Step 2:** Fail, implement, pass.

### Task 4: Line clipping

- `clip_line(p, dir) -> Vec<(f64, f64)>`: parameter intervals inside the region, from exact line–segment and line–arc intersections, sorted and merged.
- [x] **Step 1:** Tests: line through a rectangle with a hole (two intervals), tangent to a circle, along an edge.
- [x] **Step 2:** Fail, implement, pass.

### Task 5: Offset-pocket prototype

**Files:** `src/spike/{mod.rs, pocket.rs}`, `examples/s3.rs`.

- Rings: offsets of the clear region by −R, −R−s, … until empty; inside-out order; each ring a closed `Pass` of lines and arcs (`fluut-path`).
- Three test shapes (also used by Task 6): A, a 100×60 rectangle with a Ø20 island; B, an L shape with a 12 mm neck; C, a Ø80 disc with a 10 mm slot cut into it.
- [x] **Step 1:** Ring counts and total length for each shape; the toolpath stays inside the region (sampled check).

### Task 6: Adaptive-clearing prototype

**Files:** `src/spike/{engagement.rs, adaptive.rs}`.

- `engagement(p, R, uncut: &Region2) -> f64`: the angle of the circle of radius R at p inside the uncut region, from exact circle–segment intersections.
- Marching as D09 §2.3: follow the offset of the cleared region K, correct the offset distance by 1-D root finding so φ = φ*, steps ≤ R/4; K ∪= the swept region of each finished path (union of the path's offset by R).
- [x] **Step 1:** Engagement tests against numerical integration (Review Focus 3).
- [x] **Step 2:** Prototype on shapes A, B, C with R = 3, φ* = 60°: time per level, path length, maximum and RMS engagement error, uncut area left (slivers) before the final contour pass.

**Done.** Findings and numbers are in [`spikes/s3-region-2d.md`](spikes/s3-region-2d.md). Deviations from this plan:
- Booleans are split and classify over `cavalier_contours`' segment intersection, not pairwise polyline booleans.
- Prototypes produce 2-D point paths, not `fluut-path` passes.
- Engagement is checked against numerical integration to 1e-4 rad (the integration's resolution), not 1e-6; analytic cases match to 1e-12.
