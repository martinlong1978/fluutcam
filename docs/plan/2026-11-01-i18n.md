# fluut-i18n Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create `fluut-i18n` (layer 1, listed in `xtask/layers.toml` since M0) and move the application's strings, numeric entry units and number display onto it. M5 kept an English table in `fluut-app/src/text.rs` because the crate did not exist.

**Architecture:** `fluut-i18n` holds Fluent catalogs (English embedded from `locales/en/*.ftl`, a locale chain ending in English, a pseudo-locale), locale number formatting and parsing, and unit parsing and formatting. It does not depend on `fluut-model`: it has its own `LengthUnit` and `Dimension`, and the app maps `DisplayUnit` and `FieldKind` onto them. `fluut-app` keeps the expression grammar of numeric entry; the number and unit tokens come from the crate.

**Tech Stack:** `fluent-bundle` 0.16 (concurrent bundle, isolating marks off), `unic-langid`, `thiserror`. `cargo deny check` passes with them.

**Design:** [`../design/D13-ui-architecture.md`](../design/D13-ui.md) §4, §8–§9; [`../design/D15-toolpath-parameters.md`](../design/D15-toolpath-parameters.md) §1.2, §1.7; spec 08 §8.10a.

## Global Constraints

All earlier Global Constraints apply. In addition:

- A missing message id gives the id back, never a panic; a translation may be partial.
- Files and G-code never use locale formatting (spec 08 §8.10a); only UI display and entry do.
- Diagnostics resolve through Fluent only where the message has no values. Messages with values stay on the English text from `fluut-model` until diagnostics carry arguments.
- No `.ftl` content is copied from another CAM product.

## Review Focus

1. **Fallback**: the chain order, and that a missing id or a bad `.ftl` entry never panics.
2. **Entry**: `,` and `.` both accepted; one unit per product; `6index` is not `6in` followed by `dex`.
3. **Drift**: the `.ftl` text for a diagnostic equals the message `fluut-model` writes.

**Done.** Deviations from this plan:
- The pseudo-locale also accents letters (D13 §9), done on the `.ftl` source outside placeables; `text.rs` no longer wraps by hand. Single-line `id = text` messages are required for that, and a test checks it.
- `Catalog` gained `get_or` and `finish` (a fallback text that still gets the pseudo-locale decoration), used for field labels and diagnostics.
- Entry now also accepts `°`/`deg` for angles and `mm/min`/`in/min`/`"/min` for feeds, which the old parser did not.
- Only English ships. `Locale` knows decimal commas for common languages, and the app sets the number locale with `text::set_locale`; nothing picks it from the operating system yet.
- The drift test for diagnostics reads `fluut-model/src/validate.rs` as text; it stops being needed when diagnostics carry Fluent arguments (D01 `MessageRef`).
- Not done: messages with values in `validate.rs` stay on the English text, as agreed; script (`fluut-script`) messages are not moved.
